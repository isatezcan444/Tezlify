## Six defects found by auditing the module I wrote last phase (all falsified first)
1. Rows with no `wa_message_id` were written → partial unique index never conflicts → one copy per
   turn. `assert 3 == 0`.
2. Page-level INSERT error poisoned the whole run (no rollback). `assert 4 == 1`.
3. Kill-switch only read in lifespan → a manual/CLI run wrote with the flag off.
4. `status == CONNECTED` was enough → an **inactive** line got backfilled. `assert 3 == 0`.
5. Page error invisible in `/health` — *because* of #2 (catching it silenced the old counter).
6. **Unreachable tail**: `max_pages*page_size = 10_000` vs RAM 9122 ⇒ 878 headroom. Every turn
   restarted at offset 0, so once total > cap the tail could NEVER be written — silently.
   `AssertionError: ikinci tur kuyrugu yazmali`. Fixed with a per-gateway cursor (`start_offset` /
   `next_offset`, resets at end of list, `dry_run` never advances it, `/health` exposes only
   `cursor_count` + `max_cursor_offset`, never the UUID).

## Gateway: two more real defects
- **`pdoSent` shadowing** — `let pdoSent` was redeclared inside the promise executor, shadowing the
  outer one ⇒ `TIMEOUT` logged `pdo_sent:false` even when the PDO had gone out. The core of the
  diagnosis was silently lying.
- No classification. Now `failure_class` = `PDO_NOT_SENT` / `WAITER_MISMATCH` / `NO_CHUNK`, derived
  from a per-session `_historyChunkSeq` (`noteHistoryChunk`) — deliberately independent of which chat
  the chunk names, because "didn't match" requires exactly that.

## Real defect found in §4 review: `/health` leaked SQL parameters

assertion `"db down" in last_error` was *passing*. Fixed with `_safe_error()` → type + SQLSTATE only;
`exc_info=True` removed. 3 tests pin it (incl. "no UUID in /health", cursors summarised as
